# Project Plan Health Check

A read-only Streamlit application that reviews Microsoft Project (`.mpp`) and Excel (`.xlsx`) project schedules and produces a downloadable PDF health-check report.

## MVP scope

- Upload a native Microsoft Project `.mpp` file or an Excel `.xlsx` schedule.
- Convert the input into a common project-schedule model.
- Run explainable schedule-health checks.
- Review findings and limitations in the app.
- Download a PDF report.

The application does **not** create or edit MPP files, write changes back to the uploaded plan, or retain project history in a database.

## Repository layout

All application files are in the repository root. No folders are required.

| File | Purpose |
|---|---|
| `app.py` | Streamlit application entry point |
| `canonical_model.py` | Common schedule data model |
| `excel_reader.py` | Excel workbook reader |
| `mpp_reader.py` | Read-only MPXJ/JPype native MPP adapter |
| `health_engine.py` | Deterministic schedule-health rules |
| `pdf_report.py` | PDF report generation |
| `requirements.txt` | Python dependencies |
| `packages.txt` | Linux packages, including Java runtime |
| `Fictional_Project_Plan_Test_Scenarios.xlsx` | Fictional Excel workbook with seven schedule scenarios |
| `Sample_Health_Check_Report.pdf` | Example report generated from the workbook's `Data_Quality_Errors` worksheet |

## Preview sample files and the PDF report

The deployed application shows a **Preview the report before uploading your plan** section before the upload control.

- **Sample Excel workbook:** download `Fictional_Project_Plan_Test_Scenarios.xlsx`. It contains seven fictional schedule worksheets, including a clean plan and scenarios with data-quality and dependency issues.
- **Sample MPP file:** use the in-app **Download sample MPP** link. It opens the genuine `ProjectKiller-Sample.mpp` file hosted by ProjectKiller: <https://projectkiller.app/assets/ProjectKiller-Sample.mpp>. The MPP binary is hosted externally and is not copied into this repository.
- **Example PDF report:** expand **View an example PDF health-check report** in the app to preview or download `Sample_Health_Check_Report.pdf`.

The example PDF was generated from the fictional Excel workbook's `Data_Quality_Errors` worksheet. It demonstrates the findings layout and report structure. It is **not** a report generated by parsing the external MPP sample. The same PDF report structure is used for MPP and Excel assessments; actual findings depend on the data extracted from the uploaded plan.

## 1. Create the GitHub repository

1. Open <https://github.com/new>.
2. Set the owner to `sparkz00705`.
3. Set the repository name to `project-plan-health-check`.
4. Add a description such as `Read-only project schedule health checks for MPP and Excel with PDF reporting`.
5. Choose Public or Private according to your preference. The app itself has no built-in user login, so repository privacy does not make the deployed app private.
6. For the simplest upload, leave **Add a README file**, **Add .gitignore**, and **Choose a license** unchecked, then create the repository.

Your repository URL will be:

<https://github.com/sparkz00705/project-plan-health-check>

## 2. Upload the application files (flat root)

1. Download and extract the deployment ZIP on your computer.
2. Open the extracted folder. Select the files inside it; do not upload the ZIP itself.
3. In the new GitHub repository, choose **Add file → Upload files**.
4. Drag all files into the upload area. Make sure `app.py`, `requirements.txt`, and `packages.txt` appear at the top level of the repository, not inside a folder.
5. Commit the upload to the `main` branch.

After the commit, the repository root should contain `README.md`, `app.py`, `canonical_model.py`, `excel_reader.py`, `health_engine.py`, `mpp_reader.py`, `pdf_report.py`, `requirements.txt`, `packages.txt`, `Fictional_Project_Plan_Test_Scenarios.xlsx`, and `Sample_Health_Check_Report.pdf`.

## 3. Deploy on Streamlit Community Cloud

1. Open <https://share.streamlit.io/> and sign in with GitHub.
2. Click **Create app** and select **Yup, I have an app**.
3. Enter these values:

   | Setting | Value |
   |---|---|
   | Repository | `sparkz00705/project-plan-health-check` |
   | Branch | `main` |
   | Main file path | `app.py` |
   | Python version | `3.13` (select under Advanced settings) |

4. Click **Deploy** and monitor the build logs for dependency or Java installation errors.

Streamlit reads `requirements.txt` for Python dependencies and `packages.txt` for Linux packages. The files are already included at the repository root. See the [Streamlit deployment guide](https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app/deploy) and [dependency guide](https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app/app-dependencies).

**Important:** Choose the Python version carefully during initial deployment. Streamlit Community Cloud does not let you switch the Python version in place after deployment; changing it requires deleting and redeploying the app.

## 4. Smoke-test the deployed application

Before uploading a user's own plan, confirm that the top-of-page sample section displays the Excel download, external MPP download link, and embedded example PDF report.

### Excel test

1. Open the deployed app.
2. Upload `Fictional_Project_Plan_Test_Scenarios.xlsx` from the extracted package.
3. Test these worksheet tabs individually: `Clean_Plan`, `Circular_Dependencies`, `Milestone_Gap`, `Progress_Baseline`, `Data_Quality_Errors`, `Resource_Overlap`, and `Mixed_Dependencies`.
4. Select a worksheet, click **Analyse project plan**, review the findings and limitations, and download the PDF.
5. Confirm that the PDF opens and contains the selected source filename and assessment details.

Only one schedule worksheet is assessed at a time. The `README` and `Expected_Results` workbook tabs are reference material, not schedule inputs.

### Native MPP test

Use a genuine `.mpp` file, not an XML file renamed with an `.mpp` extension. A public sample used during planning is available here:

<https://projectkiller.app/assets/ProjectKiller-Sample.mpp>

Upload the downloaded `.mpp` directly to the deployed app. Check that the app reads tasks and dependencies and generates a PDF. If it fails, open the Streamlit app logs and capture the full error message for diagnosis.

**Native MPP release gate:** MPXJ is integrated as the read-only MPP reader, but native MPP parsing has not yet been verified against a real MPP file in this application. Do not treat a successful deployment build as proof of MPP compatibility. Password-protected files and unsupported/corrupt MPP files may be rejected.

## 5. Local run (optional)

The application can also be run locally from the repository root:

```bash
python -m venv .venv
```

Activate the environment, then run:

```bash
python -m pip install -r requirements.txt
streamlit run app.py
```

Native MPP support additionally requires a compatible Java runtime. `packages.txt` installs Java on Streamlit Community Cloud; it does not install Java on your personal computer. Excel input and PDF reporting do not require Java.

## Data handling and security

- The app has no built-in authentication or role-based access control.
- Do not upload confidential, personal, client-sensitive, or regulated project schedules to a publicly accessible deployment.
- Use fictional or sanitised data until the intended access controls, hosting, retention and data-handling requirements have been reviewed.
- Uploaded files are processed in temporary working directories. This MVP has no project-history database and does not write to the source plan.
